chorus terminal app mockup

Kept simple on purpose, like any AI chat app: a sidebar with your projects and their chats, a New chat button, and the real Claude Code, Codex or Antigravity screen on the right. Chorus adds a status line, a menu key, handoff, artifacts, and one shared memory and skill library for all of them. Click through the scenes or use the ← → keys. Inside the terminal, anything with a pointer cursor is clickable and works like the real app (Back, breadcrumb, menu, New chat, approvals badge, list rows); ↑ ↓ and Enter work on the menu and the lists.

Where am I, and how do I go back?

The sidebar is the map: projects, and under each one its chats. Click a project to open or fold it, click a chat to go to it. That covers most moves; ‹ Back and esc cover the rest.

How you know what is clickable

A terminal has no hover cursor everywhere, so the look itself says it. Three kinds, used the same way on every screen. Plain text is never clickable.

Button: a filled chip

Does something. The key is inside it, so the same chip teaches the shortcut. The bottom row of every screen is a row of these, like Midnight Commander's F-key bar.

y Approve  n new chat  ＋ New chat

Link: underlined accent text

Goes somewhere: a project, a chat, a file, a URL. Parts of the path in the top bar are links too.

review them ›   ~/projects/cake-shop ▾

Row: lights up under the mouse

Lists (chats, artifacts, skills, approvals): the whole row is the target. The selected row has a ▸ and a background.

▸ Cake order page   claude  idle
  Stripe webhook    codex   needs approval

Hover highlight needs the terminal to report mouse motion (xterm mode 1003, which all terminals listed below support). Terminals that support it (e.g. kitty, Ghostty, xterm; to verify with a probe) also get a hand pointer through OSC 22; the others simply keep the arrow, and the look above still tells.

Mouse and other terminals

Clicks use the standard xterm mouse protocol, so they work in iTerm2, Terminal.app, Ghostty, WezTerm, kitty, Windows Terminal, GNOME Terminal, the VS Code terminal and over tmux or SSH. The keyboard stays complete: nothing is mouse-only. With the mouse on, drag-select text with Shift held (Option in iTerm2). CHORUS_MOUSE=0 turns it off.

Commands

Everything the interactive screens do is also a plain command, so it can be scripted and tested.

CommandWhat it does
chorusThe app: sidebar of projects and chats, New chat form
chorus new [--agent claude] [--model sonnet] [--folder ~/projects/x] [--skip-permissions]Start a chat (no flags: the form opens)
chorus run <agent> [--thread <id>]Open an agent on a chat (latest chat if omitted)
chorus handoff --to <agent> [--from <chat>]Start a new chat with another agent that loads the previous chat's context
chorus threads · chorus show <id>List chats; show a chat's turns, tool calls and the chats it continued
chorus artifacts [--open | --serve]List artifacts; open one, or serve them with live reload
chorus skills [on|off|import <name>]The shared skill library: list, turn on or off for all three agents, import from an agent's own folder
chorus activity [--thread <id>]Tool calls, MCP calls, token usage and limits over time
chorus trace <run-id>Raw CLI output next to the parsed events, for debugging
chorus doctorInstalled CLIs, versions, login state, paths, verified versions
chorus mcp --thread <id>The MCP server. The AI CLI starts it; you don't run it yourself

Open questions

Decisions this mockup assumes. Each one changes the build.

Command name

The package is chorus-cli; the command you type is chorus. Proposal: keep both.

Menu key

It must not clash with keys Claude Code, Codex or Agy already use (Claude uses Ctrl+O, Ctrl+], and others). Proposal: Ctrl+Space, configurable, checked against all three CLIs.

Status line under another TUI

Keeping our line at the bottom while Claude or Codex draws full screen needs a virtual-terminal layer, the way tmux does it. Fallback if that proves flaky: status in the terminal title plus the menu key only.

Skills outside Chorus

Linking the library into ~/.claude/skills and ~/.agents/skills makes plain claude / codex / agy see the skills too, but changes the user's own CLI setup. Proposal: opt-in checkbox, off by default.

Skip permissions

A checkbox on New chat, off by default, per chat only. Proposal: no global "always skip"; the status line shows skip in amber while it is on.

Approval alerts

Badge, red ! in the sidebar and a one-line flash are always on. Proposal: terminal bell on by default (muted with CHORUS_BELL=0); desktop notifications only for chats you are not looking at.

Artifact preview

Opening files in the default app is simple. A small local preview server (chorus artifacts --serve) gives live reload while the agent edits. Proposal: both, server optional.
